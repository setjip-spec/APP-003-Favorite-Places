# 1. Назначение

«Любимые места» — персональная CRM мест, маршрутов, активностей, музеев, событий и других вариантов выхода.

Главная задача: не придумывать каждый раз с нуля, куда пойти, а иметь готовую базу вариантов и быстро отфильтровать её под текущую ситуацию.

Вторая задача: после посещения сохранять фактический опыт и постепенно превращать неизвестные места в персональную базу проверенных сценариев.

Базовый цикл:

`нашли → добавили → Не изучено → выбрали → посетили → Visit → вердикт → частота → накопленное знание`.

# 2. Главный инвариант

- `Place` = текущее накопленное знание о месте.
- `Visit` = конкретный прожитый опыт.
- `visitStatus` показывает этап места.
- `verdict` показывает текущее отношение пользователя.
- фильтры превращают большую базу в короткий подходящий список.
- история Visit никогда не уничтожается текущим состоянием Place.

Нельзя объединять Place и Visit в одну запись.

# 5. Place — основные поля

## Состояние

- `visit_status`: `Не изучено`, `Запланировано`, `Был`.
- `verdict`: `Не оценено`, `Понравилось`, `Нормально`, `Не понравилось`.
- `experience_mode`: `Эксперимент`, `Вариация`, `Проверенное`.
- `repeat_frequency`: `Не повторять`, `По настроению`, `Можно часто`, `Раз в неделю`, `Раз в месяц`, `Раз в сезон`, `Раз в год`.
- `user_rating`: 0–10 или null.
- `user_comment`.
- `is_archived`.

Новое Place автоматически:

`Не изучено / Не оценено / visits_count=0`.

## Тип и характер

- `place_type`.
- `primary_effect`.
- `tempo`.
- `venue_type`.
- `social_format`.
- `required_energy`.
- `startup_friction`.
- `physical_load`.
- `booking_requirement`.

Все enum-наборы должны опираться на `app003_reference_options` и поддерживать `is_active=false` без разрушения старых данных.

## Сезон и время суток

Отдельные поля, каждое `Да / Условно / Нет`:

- spring/summer/autumn/winter availability;
- morning/day/evening/night availability.

Нельзя хранить сезоны/время одной строкой.

## География и логистика

- `area`;
- `nearest_point`;
- `address`;
- `latitude`, `longitude` — резерв под будущую карту;
- `travel_minutes_one_way` — всегда в одну сторону от Коптево;
- `travel_range` — derived;
- `walk_minutes_from_transport`.

Диапазоны дороги:

`0–10`, `11–20`, `21–30`, `31–40`, `41–50`, `51–60`, `61–90`, `90+`.

## Деньги и время

- `activity_price`;
- `transport_cost_round_trip` — туда и обратно;
- `extra_cost`;
- `estimated_total_cost` — derived;
- `estimated_duration_minutes` — только время на месте.

Правило null:

- null = неизвестно;
- 0 = бесплатно / нулевое значение.

Если все три денежные составляющие неизвестны, итоговая стоимость тоже неизвестна.

При фильтре по бюджету Place с неизвестной общей стоимостью не считается дешёвым и не проходит фильтр автоматически.

## Описание и аналитика

- `included_description` — что реально делать / что входит;
- `potential_value` — что формат может дать;
- `personal_fit_reason` — предварительная гипотеза «почему может подойти»;
- `possible_downside` — что может не зайти;
- `source_url`;
- `conditions_checked_at`;
- `internal_notes`.

## Статистика Place

Не редактируется вручную:

- `visits_count`;
- `last_visited_at`.

Они пересчитываются из Visit.

# 6. Visit

Каждый Visit содержит:

- UUID / `visit_code`;
- `place_id`;
- `visit_date`;
- `actual_travel_minutes_one_way`;
- `actual_spent`;
- `actual_duration_minutes`;
- `glad_went`: Да / Скорее да / Скорее нет / Нет;
- `visit_verdict`: Понравилось / Нормально / Не понравилось;
- `companions`;
- `time_of_day`;
- `what_worked`;
- `what_failed`;
- `comment`.

При первом Visit Place автоматически становится `Был`.

После INSERT/UPDATE/DELETE Visit должны корректно пересчитываться `visits_count` и `last_visited_at`.

Исторический `visit_verdict` не изменяется, если позже меняется общий Place.verdict.

После нового Visit интерфейс может предложить обновить общий Place.verdict выбранным visit_verdict.

## Быстрый выбор

Основной рабочий экран. Не показывает все поля Place.

Главные фильтры:

- статус;
- вердикт;
- тип;
- помещение/улица/смешанный;
- время суток;
- социальный формат;
- максимальная дорога;
- максимальный бюджет;
- нужная мощность;
- главный эффект;
- режим опыта.

Дополнительные:

- сезон;
- стартовое трение;
- физическая нагрузка;
- темп;
- бронь;
- диапазон дороги;
- район;
- рейтинг min/max;
- частота повторения.

Все активные фильтры объединяются через `AND`.

Для времени суток и сезона базовый фильтр показывает только Place, где соответствующее availability = `Да`.

Дефолт после `Сбросить всё`:

`Статус = Не изучено`; остальные без ограничений.

Краткая карточка показывает минимум:

- название;
- статус;
- вердикт;
- тип;
- дорогу;
- стоимость;
- время на месте;
- пользовательскую оценку.

# 11. Нефункциональные требования

- интерфейс быстрый и не перегруженный;
- локальные фильтры/сортировки выполняются мгновенно после загрузки данных;
- canonical DATA — Supabase, не browser cache;
- данные сохраняются между сессиями;
- одинаковые данные на desktop/mobile после входа тем же аккаунтом;
- русский интерфейс;
- ₽;
- минуты;
- даты ДД.ММ.ГГГГ;
- минимум несколько тысяч Place без изменения пользовательской логики.

# 12. Что не делать

Приложение не должно:

- считать количество развлечений KPI;
- заставлять пользователя посещать места;
- автоматически считать «счастье»;
- удалять не понравившиеся Place;
- смешивать прогноз и фактический опыт;
- уничтожать прошлые Visit;
- превращать неизвестную цену в 0;
- считать время дороги туда-обратно основной пользовательской величиной;
- строить архитектуру вокруг Excel/Google Sheets/номеров колонок.
